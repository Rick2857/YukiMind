# Yuki-QQbot 3.0.0 实施与验收报告

本报告对应 Memory V2 第六阶段“质量评测、治理收敛与正式发布”。测试日期为 2026-08-01，
环境为 Windows、Python 3.12.13、SQLite 3.53.1 与 Docker Desktop。确定性评测只使用版本化
合成数据、Fake Model 和 Fake Embedding；生产数据库检查不导出聊天正文。

4. 当前 Alembic head：`0024`。
5. 文件范围：新增 `memory/quality/`、质量门禁与契约配置、18 个 fixture、基准和契约快照、质量/性能/迁移测试、CI job、质量架构与运维文档及本报告；修改 CLI、Memory 指标与上下文计数、版本、README、CHANGELOG、升级指南、路线图、插件兼容范围、`.env.example` 和锁文件。正式产物位于 `artifacts/memory-quality/`。
6. Quality Suite Schema：严格、冻结且 `extra=forbid` 的 Pydantic 契约，覆盖 manifest、case、event、query、expected/forbidden observation、evaluation、metric、gate、baseline、audit、hygiene、performance 和 release-check report。
7. Fixture：`tests/fixtures/memory_quality/v1/`，由 manifest 管理 18 个独立 JSON case，覆盖身份、提取、第三方、纠正、冲突、时间、检索、上下文、rebuild、隐私和幂等。
8. Symbolic identity：fixture 只写 `person_a/person_b/group_a/group_b/bot` 等符号；Loader 使用固定映射生成合成标识，断言和报告不依赖数据库自增 ID。
9. Runner：每个 case 建立独立临时 SQLite 并迁移至 `0024`，装配真实 Memory V2 服务、FTS、RRF、Context、rebuild 流程以及 Fake Model/Fake Embedding，运行后只输出结构化 observation。
10. Evaluator：只比较 observed、expected 和 forbidden；事实按作用域、符号主体/群、kind、key、规范正文、status、authority 和 conflict state 稳定键比较，证据、检索、上下文和 rebuild 均按稳定键精确比较，不用 LLM 评分。
11. 完整指标共 55 项：`case_pass_rate`、`subject_attribution_accuracy`、`scope_attribution_accuracy`、`cross_person_contamination_rate`、`cross_group_contamination_rate`、`third_party_global_leak_rate`、`bot_subject_rate`、`unknown_subject_acceptance_rate`、`fact_accuracy`、`evidence_provenance_accuracy`、`fact_without_evidence_rate`、`duplicate_evidence_rate`、`source_event_mismatch_rate`、`outbound_evidence_rate`、`bot_evidence_rate`、`blank_evidence_rate`、`fact_state_accuracy`、`correction_resolution_accuracy`、`retraction_resolution_accuracy`、`conflict_resolution_accuracy`、`conflict_coactivation_rate`、`duplicate_active_fact_rate`、`historical_regression_rate`、`idempotency_failure_rate`、`precision_at_k`、`recall_at_k`、`mean_reciprocal_rank`、`ndcg_at_k`、`wrong_target_retrieval_rate`、`empty_query_fact_leak_rate`、`context_precision`、`context_recall`、`wrong_subject_context_rate`、`wrong_group_context_rate`、`contested_context_leak_rate`、`third_party_misattribution_rate`、`rebuild_review_bypass_rate`、`rebuild_duplicate_commit_rate`、`rebuild_historical_overwrite_rate`、`rebuild_receipt_accuracy`、`rebuild_resume_accuracy`、`pipeline_error_rate`、`average_extraction_requests_per_event`、`average_consolidation_requests_per_claim`、`average_query_embedding_requests_per_query`、`average_context_characters`、`extraction_latency_p50_ms`、`extraction_latency_p95_ms`、`retrieval_latency_p50_ms`、`retrieval_latency_p95_ms`、`context_latency_p50_ms`、`context_latency_p95_ms`、`quality_suite_total_ms`、`total_model_requests`、`total_query_embedding_requests`。
12. 指标分母：每个指标在 `docs/architecture/memory-v2-quality-metrics.md` 有唯一权威定义，报告同时保存 numerator/denominator/unit；没有样本时值为 `null`。为避免把单个最大值伪装成尾延迟，少于 20 个观测时 p95 也为 `null`。
13. Quality Gate：`config/memory_quality_gates.toml` 保存 38 个确定性绝对门禁，回归段限制最大绝对下降 `0.01`、延迟比 `1.25`、模型请求比 `1.10`；阈值不硬编码在 Python 中。
14. Baseline：`tests/benchmarks/memory_v2/v1/baseline.json` 冻结 suite/数据集/门禁 hash、提交基点、Python/SQLite、55 项指标和显式大库性能快照；只有 `update-baseline` 会写入。

18. CLI：`memory quality validate-dataset`、`run --suite full`、`compare`、`report`、`update-baseline`、`performance`，以及 `memory audit`、`memory hygiene scan/apply`、`memory release-check`；契约校验由 release-check 和测试套件执行。
19. Production Audit：检查 Alembic revision、SQLite integrity/foreign keys、无证据事实、非法来源、孤儿派生数据、冲突共激活、重复 active slot、关系链、staging/receipt 和索引一致性；默认只输出计数、状态和有界内部行 ID。
20. Hygiene 可处理项：来源确定无效且非 explicit/contested 的 automatic/rebuild 事实可显式 invalidation；孤儿或过期的 FTS/Embedding 等可重建派生行可显式清理。
21. Hygiene 不自动处理项：explicit、contested、证据含义不确定、需要人工裁决的冲突、聊天事件和合法证据不会自动更改或物理删除。
22. Hygiene fingerprint：scan 对数据库目标、revision、问题类型和有序有界 ID 集生成 SHA-256；apply 必须显式提供完全匹配的 fingerprint，数据库状态变化后旧 fingerprint 失效。
