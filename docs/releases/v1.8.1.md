# Yuki-QQbot 1.8.1

这是 1.8 本地语音系统的补丁版本，重点完善 Roxy 中日双语、Yuki 主动使用语音的能力，以及
Genie/ONNX 在 Docker Desktop 上的常驻内存治理。

## 主要更新

- Roxy V2ProPlus 声线支持中文 `zh` 与日文 `jp`，日语参考音频可以用于两种目标语言。
- Planner 可按语境选择中文或日文，最终正文脚本会再次校验语言，避免错误 G2P 与缓存串用。
- 用户明确要求“用语音说、念或读”时由后端确定性强制语音；日常短聊天会应用
  `speech.default_mode`。
- Agent 新增 `send_voice` 回复效果工具，可以自主选择纯语音、文字加语音或可回退语音，不接触
  profile、模型、参考音频和文件路径。
- Yuki 的可信运行时上下文明确说明 TTS 没有 HTTP/TCP 端口，只使用
  `/run/yuki-speech/genie.sock`，不会把 Bot 8080 或 NapCat WebUI 6099 误报为 TTS 端口。
- Worker 在模型加载、切换、合成和卸载后主动 GC，并在 Linux/glibc 上执行 `malloc_trim`。
- Bot 启动只同步默认声线元数据，首次合成时再按需加载 ONNX 模型，空闲在线不再预热数 GiB 模型。
- 新增 `SPEECH_WORKER_IDLE_RECYCLE_SECONDS`，默认空闲 300 秒后回收 Worker 进程并由 Compose
  自动拉起为空载状态，以首次生成延迟换取数 GiB 内存释放；设为 `0` 可关闭。
- 新增非破坏性 Alembic `0016`，保存声线支持语言和每次生成的目标语言，保留全部现有数据。

## 升级

升级前先备份 `data/`，然后执行：

```bash
git pull origin main
docker compose --profile speech up -d --build
```

语音 Worker 不开放网络端口，不会重置 NapCat 登录数据。通过下面的命令检查状态：

```bash
docker compose exec -T bot qq-ai-bot-cli speech status
docker compose exec -T bot qq-ai-bot-cli speech genie doctor
```
