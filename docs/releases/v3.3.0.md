# Yuki-QQbot 3.3.0 发布说明

3.3.0 为主聊天链路加入 DeepSeek Responses API 与 Provider 原生联网搜索，同时保留现有
Chat Completions 和 Tavily 方案。Planner、Tool Kernel、原生工具和 Function Tool 继续共享同一套
后端权限边界。Plugin API 仍为 `1.0`，本版本不新增数据库迁移，Alembic head 保持 `0027`。

## DeepSeek Responses API

- 模型档案新增 `protocol = "responses"` 和 `native_web_search` capability；旧 schema v1 档案继续
  默认使用 `chat_completions`，可以渐进升级。
- 首期使用非流式 `POST /responses`，支持 instructions/input 映射、扁平 Function Tool、
  `function_call_output` 续接、reasoning effort、usage、completed/incomplete/failed 状态。
- Responses 工具循环保留 Provider continuation，不重复拼接 assistant/tool 消息；不完整响应只
  允许一次有界恢复，错误分类和日志不会输出密钥、完整提示词或工具参数。

## 原生联网与 Tavily 选择

- `WEB_MODE` 支持 `disabled`、`native`、`tavily` 和
  `native_with_tavily_fallback`；未设置时继续兼容旧 `WEB_ENABLED`。
- 原生模式把 `{"type":"web_search"}` 直接交给 DeepSeek，能够记录 search/open_page 事件，
  并从 annotations、成功打开的页面和最终正文 URL 中恢复真实来源。
- 原生优先回退只处理超时、暂时不可用、失败、空结果，以及明确索要来源但来源恢复为空；
  HTTP 429 不会转移到 Tavily。
- 来源仍由后端持久化、去重、隔离和渲染。Provider 生成的虚构来源块不会获得展示权限。

## 工具域与自动化自主决策

- 修复自动化意图会覆盖 Planner scope 的问题。自动化提示现在向显式 scope 集合追加
  `automation`，不会删除 `web`、`memory`、MCP 或其他已授权能力。
- `automation_create` 会作为候选能力保持可见，但系统不再强制调用，也不再禁止 Agent 使用同轮
  其他工具。Yuki 可以判断当前请求应立即查询、执行普通任务或创建持久化自动化。
- 只有 `automation_create` 返回 `confirmation=persisted` 和真实 `automation_id` 后，Yuki 才能
  声称任务创建成功。
- 工具暴露日志分别记录 Planner scope、是否追加 automation、最终有效 scope 和实际工具名，
  便于定位 Provider、Planner 与权限过滤问题。

## 配置示例

```dotenv
WEB_MODE=native
MODEL_PROFILES_FILE=config/model_profiles.toml
```

```toml
schema_version = 2

[profiles.pro]
provider = "deepseek"
protocol = "responses"
base_url_env = "LLM_BASE_URL"
api_key_env = "LLM_API_KEY"
model_env = "LLM_MODEL"
capabilities = ["tools", "reasoning", "long_context", "native_web_search"]

[routes]
chat_agent = "pro"
```

使用 Tavily 或回退模式时才需要配置 `TAVILY_API_KEY`。

## 升级

升级前建议备份 `data/`，然后只重建 Bot；`--no-deps` 不会重建 NapCat：

```bash
uv run alembic upgrade head
docker compose up -d --build --no-deps bot
```
