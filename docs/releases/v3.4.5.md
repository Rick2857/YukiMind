# Yuki-QQbot 3.4.5 正式版发布说明

3.4.5 正式版完善了 Memory V2 写入质量、Yuki 自主反思、Planner 首轮工具路由和主 Agent
短期历史身份。它以更可靠的证据归属减少错误记忆，同时保留 Yuki 通过统一变更服务自主修正
动态自我记忆的能力。

## Memory V2 写入质量

- `MemoryClaim` 增加主体依据、保留价值和来源风格三个有限枚举。
- 主体归属与长期价值判断拆为确定性策略；第二人称、Yuki 主语、mention 接收者和普通姓名不再
  无条件回退给消息发送者。
- 不确定事实进入 7 天隔离候选区，不参与 Prompt、向量检索或正式事实查询。
- 非 SELF 候选至少需要两条独立可信证据才可晋升；SELF 候选只由 Self Reflection 决定。
- 正式写入仍统一经过 `MemoryMutationService`、版本链、状态事件和 mutation receipt。

## Yuki Self Reflection

- 默认每日 `04:00、12:00、20:00`（Asia/Shanghai）运行，每日最多 9 次模型调用。
- 输入只使用真实聊天事件、确认投递的 Yuki 回复、可信工具回执和当前可见 SELF 事实。
- 支持 `create / correct / merge / contest / invalidate / noop`，并保护
  `identity:* / core:* / safety:* / system:* / permission:* / runtime:*`。
- 群经历默认仅群可见，私聊经历默认仅私聊可见；只有去除人物隐私后的抽象原则或偏好才可全局化。

## Planner 与工具成本

- 明确工具任务由 Planner 选择最小 scope，并输出规范化的“动作 + 对象” intent。
- Core 工具增加中文同义搜索标签，记录首轮工具命中、`request_tools` 使用和零结果指标。
- inherited 首批仍只提供最多 6 个相关工具；`request_tools` 是漏召回兜底，不是常规路由。
- 主 Agent 默认使用 12000 字符历史、8 次工具调用、6 次模型请求和 8000 字符工具结果上限。

## 主 Agent 历史信封

- 历史消息以稳定的 `EventRecord.id` 暴露本地事件引用，不再使用随窗口变化的临时消息编号。
- 人物身份直接使用事件发生时的群名片和原始 QQ；连续同一身份发言共享一个紧凑信封。
- reply 与 mention 关系仍保留为事件行元数据，Planner、自省和审计的输入格式不受影响。
- 输出清理器会剥离模型误复述的身份信封、事件号和关系元数据，不影响普通句子中的编号示例。

## 兼容性与升级

- Yuki 版本提升至 `3.4.5`，Plugin API 保持 `1.1`。
- Alembic head 提升至 `0030`；迁移保留已有事实，旧事实默认标记为 `legacy_unreviewed` 并继续检索。
- 本版本为 GitHub 正式 Release。升级前建议备份 `data/`，升级后可重点观察自动记忆归属、自省提案、
  Planner 首轮工具命中率、模型请求次数和群聊人物归属表现。
- 只重建 Bot 可保留 NapCat 容器和 QQ 登录状态：

```bash
docker compose up -d --build --no-deps bot
```

## 发布验证

- 970 项测试通过，1 项真实外部 Embedding 测试按配置跳过；Ruff、Mypy、迁移与 Docker 构建通过。
- 服务器部署验证包括 SQLite 完整性、Bot 健康、OneBot 重连、NapCat 登录状态保持、网易云 MCP
  继续运行和三轮自省调度启动。
