# Yuki-QQbot 3.4.3 发布说明

3.4.3 重构了短期群聊上下文的身份来源，并修复 Planner 将当前消息重复注入模型输入的问题。
历史发言现在直接使用消息到达时写入 `chat_events` 的昵称和群名片，不再依赖后续批量人物查询。

## 会话身份

- `chat_events` 新增发送者昵称与群名片快照，保留发言发生时的身份事实。
- Agent 历史中的每条消息都明确携带发送者显示名、QQ、消息 ID，以及存在时的回复目标。
- 删除旧的 `related_people` 上下文和配置依赖；被提及、被回复人物的记忆检索继续使用独立的
  `memory.max_referenced_targets` 上限。
- 历史搜索工具同步返回事件快照中的昵称、群名片与显示名。

## Prompt 与 Planner 修复

- 移除身份头中的逐条时间，减少近场历史的 Token 消耗；整体当前时间仍由运行时上下文提供。
- 输出清理器剥离模型复述的新旧内部身份头，并在历史装配时清理已经落库的旧污染文本。
- Planner 的 `messages` 现在只包含历史消息；当前触发消息仅出现在 `current_message`，不再因
  同一正文出现两次而误认为用户重复发送。
- Planner 的待处理数量、回复必要性和会话节奏仍基于完整事件窗口计算，不受去重影响。

## 实现与兼容性

- Yuki 版本提升至 `3.4.3`，Plugin API 保持 `1.1`。
- Alembic head 提升至 `0029`；迁移只为已有 `chat_events` 增加可空字符串身份快照列，不删除或
  重写已有聊天、记忆、关系、自动化及插件数据。
- 旧事件没有历史昵称或群名片时继续回退到 Yuki 或 QQ 号显示，不会进行批量补查。
- README 以端到端 Mermaid 流程图展示 OneBot、Planner、Memory、工具、自动化、插件、联网、
  多模态、输出及后台持久循环之间的真实边界。

## 升级

升级前建议备份 `data/`。只重建 Bot 可保留 NapCat 容器与 QQ 登录状态：

```bash
docker compose up -d --build --no-deps bot
```

Bot 启动时会自动把数据库从 `0028` 升级到 `0029`。

## 发布验证

- 全量测试、Ruff 与 Mypy 通过；
- Planner 回归测试确认当前消息不会同时出现在 `messages` 与 `current_message`；
- Bot 镜像构建和健康检查通过；
- NapCat 容器未重建，OneBot 登录和反向 WebSocket 连接保持可恢复。
