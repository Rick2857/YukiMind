# Yuki-QQbot 3.0.0rc1 实施报告

以下结果对应 Memory V2 第五阶段“从事件账本受控重建”。测试日期为 2026-08-01，测试环境为
Windows、Python 3.12.13、SQLite、Docker Desktop；所有测试模型均为 Fake Provider。

1. 开始 HEAD：`d7345116af30a8c9a9ec63637745da3c9b511c34`。
2. 最终 commit：本报告随交付 commit 一同提交，准确哈希记录在交付回复与 `git log -1` 中。
3. 当前项目版本：`3.0.0rc1`。
4. 当前 Alembic head：`0024`。
5. 文件范围：新增 `0024_memory_rebuild.py`、共享 extractor/processor/eligibility、`memory/rebuild/`、重建单元与集成测试、本报告和重建架构文档；修改配置、容器装配、命令、管理员能力、健康检查、事件仓储、Memory V2 模型/仓储/Worker、README、CHANGELOG、路线图、升级指南、版本与锁文件。
6. 新增枚举：processing source、run/item/review/commit 状态、receipt outcome、third-party mode、expired policy 均使用稳定枚举。
7. `memory_rebuild_runs`：保存不可变 selection/hash、事件快照、扫描/提交 checkpoint、创建者、提取契约指纹、计划统计、持久 usage、错误类别和完整状态时间。
8. `memory_rebuild_items`：以 `(run_id,event_id)` 唯一，保存 source hash、状态、尝试次数、claim 数、持久退避时间和错误类别，并随 run/event 级联删除。
9. `memory_rebuild_proposals`：以 `(item_id,claim_index)` 唯一，只保存 canonical claim、身份作用域、审阅/提交状态、审阅者、实际 action/fact/reason 和错误元数据；不保存模型原始响应或完整上下文。
10. `memory_jobs` 新字段：`processing_source`、`rebuild_run_id`、`outcome`、`completed_at`；旧行回填为 live。
11. `MemoryEventExtractor` 已从实时 Worker 抽出：一事件一请求、同会话较早上下文、结构化身份标签、实际模型路由名和供应商 usage 返回。
12. `MemoryClaimProcessor` 已从实时 Worker 抽出：统一校验、时间解析、候选、关系分类、历史保护、resolution 和 `MemoryFactService` 提交。
13. Live Worker 直接复用共享 extractor/processor，仍按事件立即提交，不创建 rebuild proposal，receipt source 保持 live。
14. Selection Schema 支持 all、Bot/发送者/群/作用域、时间、事件 ID、最大事件数、failed live job、third-party 和 expired policy；规范化后不可变并哈希。
15. Eligibility：仅 inbound 真人、发送者非 Bot、非空正文、允许 origin、精确 private/group 作用域且无受保护 receipt；领域判断与 SQL 共用同一策略。
16. Plan 统计：使用 SQL 返回 matched/eligible、已处理、live pending/processing、failed、私聊/群聊、字符数、时间范围和预计提取请求数，不调用模型。
17. Snapshot：plan 固定 `snapshot_max_event_id` 与时间；之后新增事件不进入该 run，resume 不扩大范围。
18. Keyset：账本扫描按 `(occurred_at,event_id)` 单调 checkpoint；不使用全表 OFFSET。
19. Source Event Fingerprint：对事件 ID、Bot、发送者、作用域、方向、正文、消息段、回复、origin 和时间做 canonical SHA-256；视觉派生摘要不影响指纹。
20. 历史 mention/reply：只接受持久 `yuki_context`、数字 at 段、或同 Bot 同群回复事件作者；不按昵称、正文、FTS 或向量猜人。
21. Extraction phase：配置化有界并发，持久 item lease、指数退避和最多尝试次数；空事件不调用模型。
22. Proposal staging：仅保存通过 SubjectResolver 与 ClaimValidator 的 canonical claim；extract 不查冲突、不写事实/证据/Embedding。
23. Review：展示有界分页的主体、作用域、操作、类别、正文、置信度、authority、时间和证据摘录；普通 status/health 不返回正文。
24. Approve/reject：支持 all、明确 proposal ID 和结构化 filter；条件更新幂等，记录真实管理员和审阅时间。
25. Commit 顺序：按源事件 `occurred_at`、`event_id`、`claim_index` 串行执行并保存 checkpoint。
26. Commit 重验：重新加载事件、校验 source hash/eligibility/receipt/subject/claim，再按当前数据库候选重新计算 action。
27. HistoricalResolutionGuard：较旧冲突只能形成 superseded 历史版本或 noop，不能反向修改较新的当前事实。
28. `last_confirmed_at`：相同历史证据合并时取 `max(existing,evidence_time)`，不会被改早。
29. 过期 claim：默认 skip；`stage_invalidated` 只创建带 expired 原因的 invalidated 历史事实。
30. 容量保护：rebuild 不调用当前 active 淘汰路径；满容量时拒绝新 current fact，但允许证据合并与非活跃历史版本。
31. Event receipt：`memory_jobs.status=done` 仍是唯一权威 receipt，outcome 区分 applied/no_claims/all_rejected/already_processed。
32. Proposal 幂等：唯一约束、source hash、review/commit 状态、事实证据约束和 receipt 共同阻止重复写入。
33. Pause/resume/cancel：Repository 条件更新驱动状态机；cancel 会取消本进程正在执行的模型 task，但不回滚已提交事实。
34. Process restart：启动时只把遗留 extracting/committing 改为对应 paused；Worker 不自动 start/resume。
35. `/ai forgetme`：清除人物 staging，取消只针对该人物的非终态 run，移除或脱敏 selection 中的 QQ，并沿用现有事实/事件删除语义。
36. FTS/Embedding：commit 仅经共享 `MemoryFactService`；FTS 触发器即时同步，active 新事实沿用现有 Embedding job，失败不回滚事实。
37. 管理命令：实现 list/plan/start/status/pause/resume/cancel/review/approve/reject/commit/retry/purge。
38. Admin Tool Kernel：实现十个 `admin_memory_rebuild_*` 工具，与命令共用服务和真实当前事件超级管理员鉴权；不能绕过 review。
39. 新增配置：enabled、轮询、扫描批次、提取并发、提交批次、上下文、重试、审阅页、摘录长度和可选 run 上限；默认不开放重建。
40. Health/metrics：健康状态只返回无正文 run 数和 in-flight 数；status 持久累计 extraction/consolidation 请求、供应商 token、毫秒延迟、receipt、action 和 Embedding job 数。
41. 迁移测试：全新安装、`0023→0024`、拒绝活动 run downgrade、`0024→0023→0024` 均通过；真实库升级前后 17/4749/96/103/268 条核心记录完全一致。
42. Plan 测试：证明 plan 不调用模型、不建 item/fact，空白和 outbound 事件不可用，统计与固定快照正确。
43. Pagination/checkpoint 测试：相同时间事件按 ID 稳定排序，快照后新增事件被排除，checkpoint 可续跑。
44. Extraction 测试：一事件一请求、空正文短路、并发不超过配置、失败持久退避、证据必须逐字来自当前事件且语义锚定。
45. Third-party 测试：trusted metadata 只允许真实 mention/reply，且不能跨群；disabled 不提供第三方主体。
46. Review 测试：分页内容有界、filter 生效、审阅者写入、重复 approve/reject 幂等。
47. Commit 测试：未完成 review 时拒绝；提交重新验源并建立事实、证据与唯一 receipt。
48. Historical Guard 测试：旧居住事实不会覆盖较新 active 事实，旧版本仅以非活跃历史形态保存。
49. 幂等测试：重复 proposal/review/commit、live receipt 竞争和源事件变化均不重复事实或证据。
50. Pause/resume/cancel 测试：状态条件更新、重启暂停、并发 run 排他和取消边界已覆盖。
51. 隐私测试：事件级联清理 staging、forgetme 删除主体 proposal/脱敏 selection；日志、health/status 不含正文或身份清单。
52. 共享管线回归：live 仍即时写事实，rebuild extract 只暂存，commit 与 live 使用同一校验、候选、分类、策略和事实服务。
53. FTS/Embedding 回归：现有索引套件继续通过；rebuild 复用相同派生路径，status 可统计本 run 实际关联的新 Embedding job。
54. 命令/权限测试：非真实 SUPERUSERS 不能 plan/list/操作 run；命令与十个工具共用服务；Plugin 无 rebuild 接口。
55. 性能测试：独立临时库 100,000 条合格事件，SQL plan 0.146 秒，1000 条/页 keyset 全扫 8.877 秒，`tracemalloc` 峰值 3.00 MiB；这是本机测量，不作为跨机器延迟承诺。
56. 完整离线集成：事件账本 → plan → start → extraction → review → approve → commit → receipt/fact → completed 使用 Fake Provider 通过。
57. 全部测试：最终收口共 701 项，结果为 700 passed、1 skipped（Qwen 在线集成显式关闭）。
