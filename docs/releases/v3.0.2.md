# Yuki-QQbot 3.0.2 发布说明

3.0.2 是群聊表情可靠性热修，不新增数据库迁移，不清理或改写聊天、人物、记忆、关系、自动化
或表情数据。Alembic head 保持 `0024`。

## 修复内容

- 修复群聊候选 SQL 的 auto-correlation：外层启用作用域和当前群禁用覆盖使用独立 alias。
- 明确的“发个表情”请求使用确定性 Planner 快路径，不调用 Planner LLM、Chat Agent 或工具。
- Planner 超时、非法响应与供应商错误使用不同降级原因；降级不再继承 MCP、自动化、管理员或
  OneBot 工具权限，普通文字最多进行一次无工具 Agent 请求。
- 表情准备返回强类型状态。无候选、仓库不可用、资产或文件缺失都不会让整轮聊天静默。
- OneBot 发送必须返回真实消息 ID 才算成功；不再生成本地假 ID 冒充平台回执。
- 媒体失败只恢复当前 ReplyEffect：optional 继续正文，preferred 和 emoji-only 给出简短、真实的
  失败说明，不重试、不换图、不重新规划。
- 平台成功后的账本或使用记录失败不会导致重复发送；下一轮只会看到当前精确会话最近三条真实
  `recent_delivery` 元数据。
- 自主群聊后台任务现在统一消费异常并释放引用，不再留下未观察的 task exception。

## 升级

```bash
git pull origin main
docker compose up -d --build bot
```

NapCat 容器与 QQ 登录数据不需要重建。本版本没有 `.env` 新增项，也没有 `0025` 迁移。

## 验证重点

在私聊和至少两个已启用群中分别测试“发个表情”，然后测试空表情池、临时移走一个表情文件和
模拟 OneBot 发送失败。成功时应看到真实图片与使用记录；失败时只应看到真实文字说明，不能出现
“已经发了”却没有图片、整轮沉默或同一图片重复发送。
